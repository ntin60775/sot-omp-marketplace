# 01: Материализация и непроверяемые плагины

**What to build:** `check` перестаёт доверять реестру маркетплейса как
доказательству поставки и перестаёт краснеть из-за того, что проверить нельзя.

**Материализация — новый жёсткий вид `materialization`.** Сейчас `observe()`
читает `omp plugin list --json` и на этом останавливается: плагин может быть
зарегистрирован, а payload — недоступен. Проверять (и в проектном
`<project>/.omp/plugins/node_modules`, и в user-scope корне):

- `installPath` наблюдаемого плагина существует;
- у каждого наблюдаемого плагина есть запись в `node_modules`, которая
  **разрешается в его `installPath`** (симлинк с такой целью либо каталог) —
  сопоставление именно по цели симлинка, потому что имени пакета в
  `omp plugin list --json` нет (поля только `id`, `scope`, `installPath`,
  `version`, `installedAt`, `lastUpdated` — проверено 2026-09-18);
- в `node_modules` нет битых симлинков.

Нарушение — строка `materialization` с путём и, для симлинка, с его целью.
Лечение в отчёте называть то же, что в runbook: `omp plugin upgrade
<id>@<marketplace> --scope=project` в затронутом проекте.

**Непроверяемый плагин — мягкий вид `unversioned`.** Сегодня «каталог знает
плагин, но `version` не объявлена» даёт жёсткий `unknown` с неверным текстом
(«плагина `redaktura-skills` нет в каталоге `redaktura-skills`»). Разделить:

- `unknown` (жёсткий) — каталог плагина не знает: опечатка в `id`,
  незарегистрированный маркетплейс, пустой кэш;
- `unversioned` (мягкий, рядом с `pinned`/`own-rules`) — каталог плагин знает, но
  версии не объявил: обновлять нечего, и текст говорит именно это.

`_adopt_candidates` такие плагины в ожидаемый состав **не вносит** и печатает
строку «не отслеживается: каталог не объявляет версию» — иначе принятие
потребителя сразу краснит гейт (так вышло с `project-bp` 2026-09-17).

**Blocked by:** None (can start immediately).

- [x] `observe()` проверяет материализацию в обоих корнях; мёртвый `installPath`,
      битый симлинк и отсутствующая запись дают **жёсткий** `materialization`
      (exit 1), текст содержит путь и цель симлинка
- [x] Фикстуры: битый симлинк; отсутствующая запись у наблюдаемого плагина;
      несуществующий `installPath` — каждая даёт `materialization` и exit 1
- [x] `drift_for`: «каталог знает, версии нет» → мягкий `unversioned`; «каталог не
      знает» остаётся жёстким `unknown`; мягкий вид не делает гейт красным
- [x] `_adopt_candidates`: плагин без объявленной версии в `plugins[]` не попадает,
      в отчёте — строка «не отслеживается: каталог не объявляет версию»
- [x] Фикстуры на оба поведения `unversioned` (отчёт и принятие)
- [x] `python3 -m pytest tests/` зелёный; `gitmark lint` зелёный
- [x] На живой машине новый вид не даёт ложных срабатываний: `check` по 12
      потребителям показывает ровно то же, что до правки (кроме новых видов,
      которых сейчас быть не должно)
- [x] Воспроизведение инцидента: во временном проекте (или на копии) симлинк
      `node_modules/<pkg>` переводится на несуществующую цель → `check` краснеет
      `materialization`; после возврата цели — зелёный
